# Changelog

## 0.1.5

- Fixed Quick Access card duplication when switching between table/card inventory views. Resource badges no longer expose the generic `data-item-id` attribute used by Quick Access to discover item rows.
- Resource badge item identity now uses the module-private `data-fblr-resource-item-id` attribute, preventing generated controls from being mistaken for additional inventory items by other modules.
- Added a regression test for generic item-row selector collisions.

## 0.1.4

- Reworked Actor-sheet resource badges for performance. There is now one delegated click listener per open Actor sheet instead of one listener per resource Item.
- The MutationObserver is now created only when Quick Access is active, observes only the Gear tab, and decorates only newly-added row/card subtrees instead of rescanning the entire inventory after every DOM mutation.
- Observer records generated by this module's own badge insertions are discarded, preventing redundant follow-up callbacks.
- Added per-Item operation serialization for roll, split, and transfer actions to reject accidental overlapping operations from duplicate clicks/open sheets.
- Resource die and resource-weight setters are idempotent: if the effective flag/weight is already correct, no Document update and no render occurs.
- Resource rolls now apply the mechanical result before chat presentation, so a ChatMessage failure cannot leave the resource state inconsistent with the rolled result.
- Split operations suppress the intermediate Item update render. A normal split now produces one Actor-sheet render rather than two.
- Partial Transfer creates its temporary split Item with rendering disabled; Item Piles success or rollback supplies the single visible render.
- Quantity normalization suppresses its intermediate quantity-reset render and restores the original quantity if copy creation fails.
- Existing hidden-quantity migration is batched per Actor with rendering disabled instead of normalizing every Item one-by-one. The migration version is unchanged, so worlds already migrated by 0.1.x are not rescanned.
- Quantity hooks now ignore module-owned normalization/split documents and bail out on the common `quantity <= 1` path before calling Item Piles detection.
- Quick Access menu integration now uses a microtask instead of `setTimeout(0)`, removes global pending state, and resolves the owning Foundry application directly through `data-appid` before using the compatibility fallback scan.
- Optional Item Piles initialization and inventory migration are isolated so one integration failure cannot prevent the other subsystem from initializing.
- Item-sheet resource controls now honor sheet editability and temporarily disable action controls while asynchronous work is running.
- Added regression tests for render suppression, observer behavior, migration batching, Quick Access scheduling, operation serialization, and no-op Document updates.

## 0.1.3

- Fixed a hard browser/UI freeze when a resource badge existed on an open Actor sheet. The badge MutationObserver was retriggering itself because every decoration pass rewrote the badge text node even when the value had not changed. Badge DOM writes are now idempotent.
- Removed redundant immediate/microtask/timeout Actor-sheet decoration passes; the single initial pass plus MutationObserver is sufficient.
- Resource select changes now stop propagation into Forbidden Lands' native auto-submit ItemSheet form, preventing duplicate Item updates/renders from one selection.
- Item Piles world integration settings are now written only by a GM, avoiding player-side attempts to mutate world settings.

## 0.1.2

- Fixed the gear item Resource editor vertical alignment. It now follows the native Forbidden Lands `.weight` layout (`flex-direction: column` with the same `0.5rem` gap) and participates normally in the parent MAIN grid's `align-items: end`.
- Removed the `align-self: start` override that caused the Resource control to sit visibly higher than Weight.

## 0.1.1

- Fixed resource badges not appearing in either the normal Gear table or Quick Access card view. The renderer was selecting the Gear tab navigation button instead of the Gear tab content.
- Resource controls are now added only to `gear` Item sheets. Weapon and Armor sheets are left untouched.
- Reworked the Resource field to occupy one native MAIN-grid cell cleanly. The select now uses the full field width, while action icons sit beside the label.
- Added configurable automatic weight per resource die.
- Added default weights: d12 Normal, d10 Light, d8 Light, d6 Tiny, d4 Tiny.
- Resource depletion, manual die changes and splitting now update Item weight automatically in the same document update where possible.
- Split resources now receive independent correct weights, and cancelled partial transfers restore the original weight.
- Added Item Piles `UNSTACKABLE_ITEM_TYPES` integration for `gear`, `weapon` and `armor`, keeping the existing quantity normalizer as a fallback.

## 0.1.0

- Added per-Item resource dice (`d4`, `d6`, `d8`, `d10`, `d12`).
- Added automatic 1–2 depletion with the standard `d12 → d10 → d8 → d6 → depleted` ladder.
- Kept `d4` as an explicit special resource that depletes directly rather than becoming the default minimum die.
- Added resource splitting according to the Air Islands campaign rule.
- Added resource-aware partial Transfer through Quick Access + Item Piles.
- Added Item Piles similarity integration so resources with different current dice cannot be silently merged.
- Added clickable inventory badges in the standard gear table and Quick Access card layout.
- Added a Resource editor to supported Item MAIN tabs.
- Added automatic unstacking of `gear`, `weapon`, and `armor` in character inventories while preserving `rawMaterial` quantities and Item Piles merchant stock.
- Added one-time migration for existing hidden quantities.
